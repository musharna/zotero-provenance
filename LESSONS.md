# Lessons

One line per miss: date, the class of miss, the mechanism that now catches it.

- 2026-09-16 (fuzz #14) A "never block a turn" guard whose `try` began after work that could raise, and three pure parsers whose stdlib calls raise on input their contract promised to answer (`Path.exists` on ENAMETOOLONG, `inet_aton` on NUL, `int(x, 16)` on a non-digest). No lint can type-infer `Path.exists` or tell a guard's scope from its intent, so no hook was added; the weekly `fuzz` job caught it, and each case now has a seen-failing test with a positive control.
- 2026-09-16 (PR #17 review) "Each test was seen to fail" was true per test and false per assertion: a test stops at its first failing assert, so a NUL assertion placed after it never ran against the old code, and it passes there too. Its claim went into a docstring and this file. Caught by the CI `review` job; a multi-case fix now checks each case against the old code on its own, not only the test as a whole.
- 2026-09-16 (offline gate) The User-Agent test injected a mock transport and was believed offline for four weeks, but `GuardedTransport` resolves the host with the real `socket.getaddrinfo` BEFORE the request reaches any transport, so the test did a live DNS lookup on every run and, with no network, the guard refused the host and no request was made. Caught by the new `Tests with no network` CI step (the suite in an empty network namespace); `build_fetch_client` now passes the guard's `resolve` seam through, and a test proves the injected resolver is the one the guard uses.
- 2026-10-02 (#43) A fixed per-hook wall-clock budget (`zp_timeout 10`) wrapped work that grows with the message: about 1.2 s per new URL, so 5+ URLs were killed mid-POST, and every e2e test cited one URL against an instant fake, so none could reach the limit. The first diagnosis blamed Claude Code cancelling hooks; the 10 s figure was the plugin's own. Now caught by an e2e test that cites four URLs against a fake Zotero whose POSTs take 3 s (seen failing on the inline path), and the hooks hand the work to a detached worker bounded by its own deadline.
- 2026-10-02 (PR #44 review) A fork-failure fallback was written as if one process ran `_detach()`, but three do: a failed second fork raised in the intermediate child, which then captured inline with no deadline and no `timeout` while the hook waited on it. The fork-failure test patched `os.fork` to fail on every call, so it only ever failed the first fork. Caught by the CI `review` job; a test now forks for real and fails only the second fork, and the intermediate child can only exit.
- 2026-10-02 (PR #44 second review) The first review's fix closed the instance it named (the second fork) and not its class (any step that can fail in a process other than the hook): the /dev/null redirect still ran in the worker after the hook had returned, so an EMFILE there fell back to an inline capture holding the hook's stdout. Caught by the CI `review` job again; every fallible step now runs in the intermediate child, and each one has a real-fork test that fails only that step.
